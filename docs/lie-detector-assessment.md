# 冒险岛测谎触发评估

样本：开本工具约 2 小时，测谎 2 次；以前不开，自称从未测谎。对照源码 `window_capture.py` / `vision.py` / `app.py` / `overlay_window.py`。评估日 2026-08-29。

## 结论

两次测谎**不能证明**是本工具触发的。约 2 小时连续刷图本身就是官服测谎的常见门槛。

若客户端额外加了权重，本仓库里唯一对得上「图色辅助指纹」的，是对冒险岛窗口做持续 **Windows.Graphics.Capture**（`CreateForWindow`），而不是 OCR 算法，也不是读内存。

| 观测 | 含义 |
| --- | --- |
| 2h / 2 次 | 今晚样本 |
| n = 1 | 无法做因果推断 |
| WGC 绑窗 | 工具侧最高嫌疑 |
| 刷图时长 | 与测谎弹窗症状最吻合 |

## 两种解释，权重接近

「以前不开从没测谎、今晚开了测了两次」是相关，不是因果。同时发生了两件事：开了这个进程，以及连续刷了约两小时。测谎弹窗是服务端人机校验，不是 HackShield 那种直接踢线。

### A. 服务端刷图测谎（更吻合症状）

官服测谎分弹窗校验和后台行为。公开描述里，连续约 2 小时无社交、同一图机械刷怪，会弹测谎。热门图、热门区更密。2 小时内 2 次，和「时长门槛 + 热门图」兼容，不必引入第三方工具。

混淆：以前「不开」也可能是以前没连刷两小时。工具和时长绑在一起了。

### B. 本工具的采集指纹（若客户端加了码）

本工具不读内存、不注入、不模拟键鼠。它做的是：枚举标题含「冒险岛 / MapleStory」的窗口，对该 HWND 建立持久 Graphics Capture 会话，锁定后约每秒抓整窗再裁经验条，OCR 出数字。这是标准图色辅助链路。若反作弊把「有进程在抓这个 HWND」当成软嫌疑，服务器可能加测谎而不是直接封。

硬检测更常见的结果是断线/弹反外挂，不是测谎。所以 B 只能当加权，不能当实锤。

## 本工具各方式的嫌疑排序

相对权重是对「若本进程被客户端看见，哪段 API 最像辅助」的判断，**不是**测谎次数分解。依据：当前仓库实现。

相对嫌疑（合计 100）：绑窗 WGC 55 · 每秒整窗 20 · 置顶分层窗 12 · 枚举窗口 8 · mss 回退 5。

| 排序 | 方式 | 代码实际在做什么 | 和测谎的关系 | 判断 |
| --- | --- | --- | --- | --- |
| 1 | Graphics Capture 绑 HWND | `create_for_window(游戏窗口)` + `start_capture()`，并关掉黄框 `is_border_required=False` | DWM 级「有人在抓这个窗口」。图色脚本的典型入口。关黄框等于隐蔽采集。 | 工具侧第一嫌疑 |
| 2 | 锁定后约 1 Hz 整窗采集 | `LOCK_SCAN_MS=1000`；`grab_region` 仍先 `grab_hwnd` 整窗，再按经验条裁切 | 2 小时约 7200 次整窗 GPU→CPU 拷贝。频率和挂机监控器一样。 | 把 1 放大，不是独立机制 |
| 3 | 置顶分层 HUD | 主窗 `-topmost`；悬浮窗 `overrideredirect` + `WS_EX_LAYERED` + `UpdateLayeredWindow` | 像外挂 HUD。反作弊爱扫这类窗。但测谎弹窗通常不是「发现 overlay 就验证码」。 | 封号/踢线风险高于测谎 |
| 4 | EnumWindows 找游戏 | 标题含「冒险岛」或 maplestory，且面积够大，记下 HWND | 单独很弱。和绑窗采集叠在一起，就是「这个进程在找冒险岛」。 | 指纹的一部分 |
| 5 | mss 桌面截图回退 | WGC 失败才 BitBlt/DXGI 抓屏幕区域或整桌面 | 老式图色手法。若状态是「监控中」，主路径多半是 WGC，不是这条。 | 仅失败路径 |
| — | OCR / 模板匹配 | OpenCV 对经验标签、RapidOCR 读数字，全在本进程里算 | 游戏进程看不到这次计算。除非扫别的进程内存里的 UI 模板，一般不单独触发测谎。 | 不是触发面 |

## 采集链路（锁定之后每秒在干什么）

README 写的「屏幕监控、不读内存」是对的。下面这条才是反作弊能看见的面。

| 步骤 | 函数 | 频率 | 对游戏进程的接触 |
| --- | --- | --- | --- |
| 找窗 | `vision.find_game_window` → `EnumWindows` + `GetWindowText` | 搜索中每 3s；锁定后不再枚举 | 只读窗口列表，不进进程 |
| 开会话 | `window_capture._ensure_session` → `CreateForWindow` | 每个 HWND 一次，然后一直开着 | DWM 对该 HWND 注册采集会话 |
| 出帧 | `Direct3D11CaptureFramePool.try_get_next_frame` | 锁定后约 1s 一次 | 整窗纹理拷到 CPU |
| 裁条 | `_grab_from_game_window` 按虚拟屏坐标切片 | 每次 tick | 本地裁切，游戏看不到 |
| 识别 | `find_label` + RapidOCR + `pick_exp` | 每次 tick | 纯本地，无输入回写 |

关键点：锁定后并不是「只截经验条那一小块」。WGC 会话抓的是整个客户区，裁切发生在本进程。对反作弊来说，这和全屏录像器绑在游戏窗口上没有区别。

## 明确排除的方式

- **没有读内存**：无 `OpenProcess` / `ReadProcessMemory`。经验数字只来自像素。
- **没有注入、没有挂钩**：无 DLL、无 `SetWindowsHook`、无远程线程。
- **没有替你按键或点鼠标**：无 `SendInput`。测谎题要人答，本工具也不会去答。

## 为什么「测谎」不像硬核反外挂命中

测谎是限时答题（数字/点图/指令），答错通常踢线。HackShield / 驱动级命中更常见的是立刻断线或弹反外挂。该症状更像服务器在问「你还是不是人」，而不是「抓到作弊模块」。

| 现象 | 更像什么 | 本工具能否解释 |
| --- | --- | --- |
| 2 小时内测谎 2 次 | 刷图时长 / 热门图后台校验 | 不能。不开工具、连刷两小时也可能这样。 |
| 开工具的晚上才出现 | 相关，样本只有一晚 | 可能是时长混淆，也可能是 WGC 加了软权重。 |
| 没有立刻封号或反外挂弹窗 | 不是内存挂/注入被实锤 | 符合：本工具确实没碰游戏内存。 |

## 若要分清 A 还是 B

一晚的数据分不清。要分开「两小时刷图」和「这个进程」只能换条件再看。

| 对照条件 | 若仍测谎 | 若不再测谎 |
| --- | --- | --- |
| 同样地图、同样约 2 小时，不要开本工具 | 主要是时长/地图，不是这个程序 | 本进程（尤其绑窗采集）有贡献 |
| 开工具但只开主窗、悬浮层不要叠在游戏客户区上 | overlay 不是主因 | 置顶分层窗可能被扫到（仍更像踢线而非测谎） |
| 开工具但状态一直停在「定位中」失败（没有 HWND 会话） | WGC 不是主因 | 指向 `CreateForWindow` 会话 |

## 直接回答

引起冒险岛测谎的，最大概率仍是「连续刷了两小时」这条服务端规则。本工具里若有一种方式会被反作弊算进软嫌疑，那就是对游戏窗口的 Windows.Graphics.Capture 持久会话（`CreateForWindow` + 关采集黄框 + 每秒整窗出帧）。OCR、模板匹配、经验统计逻辑本身不接触游戏进程。置顶透明 HUD 更像外挂皮肤，通常对应另一类处罚，不是测谎弹窗的主路径。

依据：本仓库实现；官服测谎公开描述（弹窗人机校验 + 连续约 2 小时刷图行为）。无法从游戏服务端日志验证。单晚 n=1，结论标为评估而非鉴定。
