# 经验条图片资源

本文档是 `assets/` 三张图的规格。改文件名、裁剪范围或用途时先改本文档，再改 `scripts/crop_exp_assets.py`、`paths.py`、`vision.py` 与 `tests/test_vision.py`。

运行时**只读** `exp_label.png`。另外两张是裁剪样张和测试夹具，程序不会加载。路径由 `paths.assets_dir()` 解析：源码下是仓库 `assets/`，绿色版是包内 `_internal/assets/`。

## 文件名

固定三个名字，不要把经验数字写进文件名。

| 文件 | 1.0 尺寸（屏幕 2 + 1920×1080） | 谁用 |
| --- | --- | --- |
| `exp_label.png` | 24×13 | 运行时模板匹配 |
| `exp_bar.png` | 174×39 | 测试 / 目视检查整块经验条 |
| `exp_ocr.png` | 172×37 | 测试 OCR；对应锁定后送给识别的那一块 |

备份目录可以自定名字，根目录这三张必须用上表。

## 各张做什么

**`exp_label.png`**  
只有白色「EXP」三个字母。`find_label` 用它在窗口截图里找锚点。块头要小、内容要稳：数字和黄绿槽会变，字母几乎不变。

**`exp_bar.png`**  
整块经验条：标签、数字、百分比、黄槽。裁在底栏深色条里，去掉左边 HP/MP 和右边商城按钮。用来确认「从标签扩出去能包住整条」，以及 OCR 在稍大的图上也能读。不是匹配模板。

**`exp_ocr.png`**  
锁定监控时真正裁给 OCR 的矩形（`label_rect_to_ocr_rect`：相对标签偏移 `LABEL_IN_BAR`，宽高 `OCR_WIDTH` × `OCR_HEIGHT`）。测试读这张图，断言数字与图上一致。重裁后改测试里的期望值，不改文件名。

## 为什么曾经用数字命名

旧名 `exp_crop_67106.png`、`exp_crop_176155.png` 把图上的经验写进文件名，方便对测试。每次重裁经验一变就要改名、改测试路径，备份目录也会堆一套套 `exp_crop_*`。

经验是图里的内容，不是资源身份。身份用固定名 `exp_ocr.png`；期望整数写在 `tests/test_vision.py`。

## 1.0 尺度与备份

根目录三张按 **屏幕 2 + 1920×1080 @ 1×** 裁，匹配尺度 1.0。

屏幕 1 + 1366×768 @ 1.5× 的备份在：

`assets/屏幕1_2560x1600_1.5x_1366x768/`

该组合物理上大约 36×20 / 202×62 / 182×51，匹配尺度 1.5。备份里可以保留当时的文件名，不参与运行。

## 重裁

游戏按目标分辨率摆好后：

```
python scripts/crop_exp_assets.py
```

脚本覆盖根目录三张固定名，并打印 OCR 读数。把测试里的期望经验改成这次读数。不要再生成 `exp_crop_<数字>.png`。
