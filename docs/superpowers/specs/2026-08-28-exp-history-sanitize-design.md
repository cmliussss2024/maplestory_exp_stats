# EXP 历史自检与落盘格式

日期：2026-08-28

本功能暂时启用 TDD（本仓库默认 no-TDD；本 spec 覆盖该默认）。先写失败测试，再改实现。写完 spec 后先不写代码，等本文件通过人工审阅，再写 implementation plan。

## 目标

1. 历史行只存 `{t, exp}`，不存 `d`。`d` 由自检后的相邻有效点现算。
2. 自检在加载和每次 tick 时对整段原始序列运行。磁盘不删坏点。
3. `10001, 1010, 10204` 或 `10099, 1010×N, 10200` 中的低谷在计算时跳过。
4. 升级回落保留，升级前后收益累加。
5. 低谷持续 ≥ 10 秒且尚未跳回接上，先当升级；之后若出现跳回，整段重跑即纠正。
6. 新写入的 `t` 固定 6 位小数。

## 模块

`sanitize_exp_series(points, now) -> SanitizedExp` 是唯一自检入口。纯函数：相同输入得到相同收益。

`RateTracker` 只做三件事：追加原始点、把 `{t, exp}` 写入 jsonl、每次 tick/加载调用该函数并采用返回的 gains。

`SanitizedExp` 至少包含：`last_exp`、`gains`（`(t, delta)`）、`first_gain_at`、`last_gain_at`、`last_gain`。图表和速率仍只消费 gains，不读原始低谷。

## 落盘

新行格式（单行 JSON，键顺序 `t` 然后 `exp`）：

```json
{"t": 1787839419.038550, "exp": 275742}
```

- `t` 在记录边界按六位小数四舍五入：`t = float(format(now, ".6f"))`，写出时用 `format(t, ".6f")`，使 `038550` 这种末尾 0 也出现在文件里。不用 `json.dumps` 序列化 `t`（会丢掉末尾 0）。
- `exp` 为整数。
- 不写 `d`。加载时忽略未知键（含旧文件的 `d`）。
- 不重写已有 `exp_history.jsonl`：旧行可带 `d`、`t` 也可超过 6 位小数。
- `exp` 相对上一次**已写入**的值变化时才追加。相同 `exp` 不写重复行。回落（如第一个 `1010`）要写入，否则重启后自检看不见低谷。
- `clear()` 仍把文件截成空。

## 自检规则

对 `points` 从左到右走，维护已接受点。`now` 用于尚未结束的低谷计时。`None` 读数忽略，序列不变。第一点只做基数，不计收益。

**相等：** `exp` 与最后一个已接受点相同 → 跳过。

**上升：**

1. 若符合现有 `_is_truncated_expansion`（如 `6685 → 67106`）：接受为新基数，delta 0。
2. 否则若不符合现有 `_plausible_gain`（如 `8486 → 1359000`、`103546 → 1035461`）：跳过，已接受点不变。
3. 否则接受，`delta = new - last_accepted`。

**下降：** 先套现有 `_is_inflated_baseline`（如错误膨胀基数回到真值）：接受为新基数，delta 0。否则打开一段低谷。

### 低谷

从上一个已接受点 `a` 起，后续点凡不能「跳回接上」`a` 的，都算同一段低谷 `V`（含重复多次的 `1010`）。

点 `c` 相对 `a`、低谷末点 `v` 是**跳回接上**，当且仅当：

- `c.exp >= a.exp`
- `_plausible_gain(a.exp, c.exp)` 为真
- `_plausible_gain(v.exp, c.exp)` 为假

因此 `1010 → 10200` 是跳回（相对 `10099` 合理，相对 `1010` 不合理）。升级后 `10050 → 10150` 不是跳回（相对低谷末点也是合理小步），整段按升级后的新基数累加，不把中间收益丢掉。

低谷分类：

| 条件 | 判定 | 计算 |
|------|------|------|
| 后面出现跳回接上 | OCR | 跳过 `V`，接受接上点，`delta = c.exp - a.exp` |
| 无跳回，且 `now - V[0].t >= 10` | 升级 | 不记负收益；接受 `V[0]` 为新基数（delta 0），然后从 `V[1]` 起按普通规则继续走（上升计入、可再开低谷） |
| 无跳回，且持续 `< 10` 秒 | 未确认 | 跳过 `V`，`last_exp` 仍为 `a.exp` |

10 秒沿用 `RateTracker.LEVEL_CONFIRM_SECONDS`。不再用「新值 ≤ 旧值 5%」作为升级条件；时长 + 是否跳回即可。`10099 → 1010` 持续 10 秒会先当升级，随后出现 `10200` 则整段重跑改为 OCR。

确认升级时，确认窗口里 `V[0]` 之后已经发生的小步收益一并计入。这与旧实现不同：旧实现在确认瞬间把基数设成当时读数，窗口内 `120 → 280` 会丢掉。以本 spec 为准。

## 直播与重载

每次 `tick` 和 `_load_history` 都对当前全部原始点再跑一遍自检。先当升级、后跳回接上，不需要单独 undo：接上点进入序列后结果自然变成 OCR。

重载后 `hourly_rates(now)` 的 `now` 用当前时钟，以便文件末尾仍停在 `1010` 时按 10 秒规则确认升级。

## 测试（TDD 先写这些）

实现前先让下列测试失败，再写生产代码。现有 `tests/test_rate_tracker.py` 里落盘断言 `d` 的用例改为断言无 `d`、`t` 为 6 位小数；行为用例能继续用 `RateTracker.tick`，低谷细节也可直接测 `sanitize_exp_series`。

**OCR 低谷**

- `10001, 1010, 10204` → 跳过 1010，`total_gained == 203`，`last_exp == 10204`
- `10099` 后连续多个 `1010` 再 `10200` → 跳过全部 1010，`total_gained == 101`
- 低谷中 `1010, 1015, 1020` 再跳到 `10200` → 仍整段 OCR，收益接上 `10099`

**升级**

- `90000@0, 95000@1, 120@2, 200@3, 280@13, 360@14` → `last_exp == 360`，`total_gained == 5240`（升级前 5000 + 新级 `360-120`），无负收益
- 升级后小步爬过旧值（`10099 → 50`，之后每秒 +100，持续超过 10 秒并超过 10099）→ 不是 OCR；收益含升级后全部小步，不只 `last - 10099`

**10 秒门与纠正**

- `10099, 1010`，`now` 为谷起点后 5 秒 → `last_exp == 10099`，不把 1010 当升级
- 同上，`now` 为谷起点后 15 秒且无接上 → `last_exp == 1010`，升级前收益保留
- 15 秒已当升级后出现 `10200` → 改为 OCR，`last_exp == 10200`，`total_gained == 101`，不是 `10200 - 1010`

**保留的旧 OCR 行为**

- `None` 读数不改变速率
- `8486 → 1359000` 不当收益
- `25852, 2586, 25863` 截断回落后仍能计后续收益
- `33252, 325, 33402` 不产生巨额收益
- `6685 → 67106` 只换基数、不计巨额收益
- `103546 → 1035461` 忽略；之后回到 `107016` 并继续小步计收益
- `55497, 516, 581, 590, 55604` 不把短截断当成升级

**落盘**

- 新行只有 `t`、`exp`
- `t` 的 JSON 文本始终是小数点后 6 位（含末尾 0），例如 `1787839419.038550`
- 含 `d`、且 `t` 超过 6 位小数的旧行仍能加载
- 回落 `1010` 会写入文件；加载后再跑自检，与直播跳过该点后的收益一致
- `clear()` 仍清空内存和文件
