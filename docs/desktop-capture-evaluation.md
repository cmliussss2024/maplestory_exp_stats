# 桌面小块采集：可行性与检测面

对照见 [测谎风险评估](lie-detector-assessment.md)。当前主路径是对冒险岛 HWND 做 `CreateForWindow`，锁定后仍每秒整窗出帧，再在内存里裁经验条。

拟改：不再采集游戏进程；坐标系用虚拟桌面；锁定后只拷已经定位的那一小块；只有采不到时，才 3 秒一次整桌面匹配。

## 结论

能做成。这三条打掉的是评估里最强的那条指纹：绑游戏窗口的 Graphics Capture。

检测面会从「有进程在抓冒险岛 HWND」变成「偶尔拷桌面小块」。不再对游戏窗口建采集会话、不再按标题找「冒险岛」、不再每秒整窗出帧。从客户端看，不再干涉冒险岛窗口——对这条采集面成立。

小块 BitBlt 仍是截屏 API，只是对象是桌面合成结果，不点名游戏进程。置顶分层 HUD 这次不动。测谎是服务端判定，改完不能保证不再弹；能说明的是这条采集面比现在轻。

## 三条能否落地

| 方向 | 能否做 | 说明 |
| --- | --- | --- |
| 1. 不采集游戏进程，范围改桌面 | 能 | 关掉 `create_for_window`。坐标系是桌面，每秒并不拷整张桌面。 |
| 2. 锁定后每秒只截已定位的那一小块 | 能 | `locked_rect` 已是虚拟屏坐标；`_grab_mss_region` 已按矩形抓。经验条约 `121×34`（再乘 DPI）。`grab_region` 不再走 `_grab_from_game_window`。 |
| 3. 采不到时才 3 秒一次整桌面匹配 | 能 | 状态机已是：锁定丢 3 次 → 重新定位，搜索间隔 3 秒。搜索改为整张虚拟桌面 `find_label`，不要再 `grab_hwnd`。 |

「采集但不整屏截图」：锁定路径只 BitBlt 小矩形。整桌面只在丢锁后的搜索里出现。

## 目标链路

```
监控中（1s）：mss 只抓 locked_rect → OCR
    └ 标签连续 3 次不在 → 重新定位
定位中 / 重新定位（3s）：mss 抓整张虚拟桌面 → 模板匹配 → 写下 locked_rect
失败 20 次 → 读取失败（现有逻辑）
```

不再：`EnumWindows` 找冒险岛、`CreateForWindow`、整窗 GPU 纹理、关采集黄框。

## 会换掉什么

| 去掉 | 还在 |
| --- | --- |
| 绑游戏 HWND 的 WGC | 小块桌面 BitBlt（通用截屏，不点名冒险岛） |
| 每秒整窗出帧 | 3 秒一次整桌面，且仅在丢锁时 |
| 按标题找「冒险岛」窗口 | 置顶窗 / 分层 HUD |

代价：游戏被挡住时读到的是挡住它的像素；独占全屏若没进 DWM，小块可能是黑的（当前窗口模式可用）。游戏拖走或改分辨率后，约 3 秒脱锁，再 3 秒重搜。

全桌面匹配必须扣掉本工具窗口所占矩形。现在搜索只扫游戏窗，扫不到自己的经验条预览；改成整桌面后，预览里的标签可能被当成游戏。

## 实现顺序

1. `grab_region` 只走小块 mss，去掉每秒整窗。
2. 搜索改整桌面，匹配时排除自身窗口。
3. 删除 `window_capture` 的 `CreateForWindow` 路径。
